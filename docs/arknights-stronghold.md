# 明日方舟卫戍协议

登录本站后，从「森空岛 → 明日方舟 → 卫戍协议」进入。「卫戍战报」对站内成员开放，绑定森空岛后可同步自己的战绩。`view=mine` 打开「我的战绩」，既有 `report` 和 `view=mine&battle` 链接继续有效。管理员可在「任务管理 → 任务配置 → 森空岛 → 明日方舟」控制 `skland.arknights.stronghold`，默认关闭。

右上角的「检索条件」显示当前视图的筛选项。修改即时更新结果并回到第一页，条件保留在 URL 中；「恢复默认」恢复当前视图的默认条件，「完成」关闭面板。

## 我的战绩

- 个人历史按结束时间倒序，支持角色、版本、模式、难度和结果筛选。进入总览、切换筛选或分页后，默认展示当前页第一条；选择左栏卡片仅切换右侧战报。窄屏列表横向滚动、详情在下方。「同步角色」独立于检索条件。日报独立打开详情，返回保留原筛选、分页和位置。
- 胜率按当前角色、版本、模式和难度下，官方个人结果已知的本站战报计算。结果筛选和分页仅作用于列表。
- 「同步角色」只列出森空岛账号内已勾选「加入本站」且已识别到区服的明日方舟角色，和自动签到开关无关。取消加入会停止后续同步，不删除已有战报；「查看角色」仍可筛选历史战绩。战报同步后自动纳入全站日报，解绑或换绑不删除个人历史及日报贡献。

## 对局战报

- 日报和个人历史复用同一个对局面板。日报优先看本人，没有本人战报时展示第一份可用战报。联合模拟固定四席，同渠道同角色的重复战报归入一个席位，仍可切换不同视角。只展示已同步的游戏角色名，本人以金色边框标记，缺席显示「无可用战报」。
- 切换席位同时更新出战干员和盟约叠层数据。阵容展示干员等阶、卫戍精锐状态、养成、合成、装备及记录到的特质、技能和模组；未装备与装备未记录分别展示。叠层纵轴固定为 0–1000，只有该视角超过 1000 层才扩大。实测 `0` 与缺失 `—` 分开显示，不把不同视角值相加。
- 悬停或点击策略、装备、盟约柱查看效果，键盘可聚焦打开、按 Escape 退出。两处左栏的策略气泡优先朝右，空间不足时在上方或下方显示。已激活盟约的所属干员图鉴中，能与当前视角阵容棋子 ID 匹配的头像才显示出战对勾。没有逐局禁用数据，不提供禁用显示。

## 卫戍战报

- 「检索条件」可按版本、日期、难度、玩法和整局结局筛选。日报默认最新版本、北京时间今天、终极模拟、全部玩法和全部结局；可单独选全部版本、全部难度。最新版本按站内已开放的版本时间确定；没有已开放且带时间的版本时，取缺少开放时间但最近有可见战绩的版本。无匹配对局时保留选择，不跳到其他版本或日期。
- 日期按北京时间的对局结束日计算，联合局取各已同步视角最晚的结束时间。所有日报统计、总局数和列表从同一批已筛选的可见对局计算。列表按结束时间、本站对局 ID 倒序，每局展示一次；分页不影响统计。
- 联合局取可见视角中结算时间最新的已知 `teamComplete`。非联合局取可见视角一致的个人结果。无法判定时显示「结果未知」，只纳入全部结局。个人战报仍保留各视角自己的结束时间和结果。
- 日报和战报显示对应角色的明日方舟游戏名。缺名时可从当前绑定的角色发现记录、干员练度快照或签到角色缓存按成员、渠道、UID 补齐；个人战报也可用页面已有的森空岛绑定列表补齐对应席位。不同昵称不拼接，也不用数字 UID 或站点昵称代替。看战报不额外回源。聚合仍按站内成员 ID，展示相关角色的去重游戏名，日报页面不提供成员筛选。
- **卫戍大王**按当前检索条件下每位成员的参战总局数降序，同局多个角色或视角只计一次。同局数按成员 ID 排序，个人是否通关不影响计数。首页只展示前三名：站内头像用金、银、铜框标记，第一居中、第二在左、第三在右，头像下方显示相关游戏角色名和参战局数。
- **策略**饼图按版本和策略 ID 统计使用次数，不限于当前页。每局同渠道同角色的同一策略只计一次，未记录或重复视角报告的策略互相冲突时不计。右侧按使用次数列出前五种；从扇区和榜单均可查看该版本效果说明。
- **盟约**平铺所选版本范围内的所有资料库盟约和符合筛选的对局中已激活的历史盟约条目。每局同渠道同角色的同一盟约只计一次，一致的重复值不多计，不一致的值不计。无激活记录显示 `0`，已激活但没有可用层数显示「未知」。点开盟约可看各成员战报的累计值；角色关联多个成员时计入未归属。累计值不代表团队总叠层或个人实际产出，明确的团队口径值在同局内去重并单列，不加入角色视角累计。这些规则也适用于已入库的历史战报。
- 本站按同一活动 `activityId` 内的 `sceneId` 归并对局，不假定该标识跨活动唯一。一局保留一个对局条目及各角色视角。缺少 `sceneId` 的新条目跳过。旧视角在再次收到相同源记录时补齐归属，继续解析已有链接；同步窗口外的历史不自动重建。

## 自动同步与版本留档

- 「任务管理 → 任务配置 → 森空岛 → 明日方舟 → 卫戍协议」控制页面和任务，默认关闭。开启后，后台每分钟检查队列。现有绑定会分批识别官服与 B 服角色，新绑定验证成功时登记可用角色；手动和后台战绩同步都只处理已加入本站的角色。
- 普通角色默认每 30 分钟同步，最近 2 小时有已知战绩的角色默认每 10 分钟同步，两项可独立配置。「我的战绩」中的「立即同步」提高所选角色的队列优先级，同角色两次请求至少相隔 5 分钟。上游请求限并发、分批执行并留有间隔。收到 429 时全站同步尊重 `Retry-After`，临时失败自动退避，绑定确认失效后暂停该绑定。
- 目前可用的森空岛接口返回滚动历史。任务会检查窗口内的全部条目，保留窗口外已入库的记录。同一对局的同一角色保留结束时间较新的视角，不用旧快照覆盖新结果。本站实际样本曾返回 100 条，历史窗口大小可能随森空岛变动。
- 版本和活动从明日方舟数据仓 `gamedata/excel/activity_table.json` 自动发现。活动结束前及结束后的两天内会同步。数据仓暂未就绪时使用已知活动。配置文件 `config/jobs.json` 的 `scheduler.arknights_stronghold_sync.activity_ids` 可补充待拉取的活动 ID。
- 森空岛正式资源按 `(activityId, versionId)` 保存名称、描述和图片映射。同一活动的资源供所有角色共享，通常每日更新，发现新版本时可提前刷新。已结束且有快照的旧版本保留原资源。图片校验后按内容哈希存到 `data/runtime/stronghold/assets/`，随站点备份保留。缺失的版本图片使用基础主题和可用图标。
- 同版本游戏表补充策略发起者、初始生命值、盟约激活条件、所属干员、干员特质和首领资料，并提供没有森空岛资源时的效果和原版 CDN 图标。精锐状态读取同版本棋子 `isGolden`，独立于 `evolvePhase`；对勾以同版本普通棋子 ID 匹配精锐和普通棋子，缺映射时只比对原棋子 ID。技能和模组按战报中实际记录的 ID 匹配，级别来自该版棋子配置，技能和模组文本标为干员资料，不能当作战报实测数值。
- 这些补充资料由「外部仓库更新」同步明日方舟资源仓后，在卫戍协议任务中读取入库。只有活动和版本都匹配才补全；已归档版本只补缺项，不覆盖旧效果或借用其他版本资料。

## 森空岛原始字段

本站用成员绑定的森空岛会话读取 `garrison/info` 的 `history.records`，并用 `garrison/resource` 对应 `versionId` 的资源解析名称、描述与图标。已知活动 ID 为 `act3autochess`。战绩与资源使用独立请求，缓存的资源可在上游暂时不可用时继续显示。

| 官方字段                                                                      | 含义及用途                                                                                 |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `id`、`sceneId`、`versionId`、`activityId`                                    | 角色战报 ID、活动内对局标识、资源版本和活动 ID。角色 `id` 含 UID，本站仅保存必要的派生键。 |
| `gameStartTs`、`gameEndTs`                                                    | 开始和结束的 Unix 秒时间戳，用于时长和日报归属。                                           |
| `modeType`、`modeDifficulty`、`mode`                                          | 模式、难度 ID 和难度显示名称，作为筛选条件。                                               |
| `completeState`、`teamComplete`、`passRound`                                  | 个人结果、队伍结果和回合。联合局的个人结果和队伍结果可不同。                               |
| `bandId`、`title`                                                             | 策略 ID、称号信息，策略名称和图标来自对应版本资源。                                        |
| `chessSquad`                                                                  | 阵容中的干员、等级、合成、技能、模组和 `equips` 道具。干员特性可通过版本资源补充。         |
| `bondInfo`                                                                    | 盟约、激活状态和该视角记录的叠层。联合局未标明实际产出者，本站保留原值。                   |
| `trophyBefore`、`trophyAfter`、`coinCost`、`syncCnt`、`killCnt`、`acBossInfo` | 局前后奖杯、认证消耗、同步次数、击杀数和首领记录。                                         |
| `events`、`canPublish`                                                        | 官方返回的事件数组和发布标记。本站未使用这两个字段。                                       |

开发环境的一局 `MULTI` 联合模拟返回了以下统计原值。样例节选移除了角色、场景和时间标识。

```json
{
  "modeType": "MULTI",
  "completeState": 1,
  "teamComplete": 1,
  "passRound": 15,
  "killCnt": 280,
  "syncCnt": 4,
  "coinCost": 164,
  "trophyBefore": 643,
  "trophyAfter": 651
}
```

`bondInfo` 的每项包含 `bondId`、`activate` 和 `layer`。`chessSquad` 的每项可带 `chessInfo` 和由 `{ "equipId": "…" }` 组成的 `equips`。`acBossInfo` 的每项带 `bossId`、`isHidden` 和 `isKilled`。

`GET /me` 和 `GET /views/{view_id}` 读取当前成员的个人历史，`GET /community` 和 `GET /reports/{match_id}` 面向站内成员。对局详情的 `player_group_id` 是该局内的不透明分组标识，`is_own` 标识由当前成员同步的战报；不公开其他玩家的数字游戏 UID。战报和详情请求均为 `Cache-Control: private, no-store`。`POST /sync` 接受刷新请求后返回 202，`GET /me` 回报同步状态。游戏图片可长时缓存。测试夹具使用脱敏字段。

日报页面显式请求 `version=latest` 和 `difficulty=abyss` 以应用默认值；直接调用 `GET /community` 时省略版本或难度则不限该项。`selected_version_key` 返回实际使用的版本键；不限版本或请求最新却没有可确定的版本时为 `null`。`result` 只接受 `complete` 或 `interrupted`，省略表示不限。兼容旧调用方的 `season`、`member` 参数也作用于整批对局；按成员选中对局后仍统计该局的所有可见视角。
