# Agent 工作流程

本文件定义 AI Agent 在本仓库的通用工作方法。项目行为与技术约束以 [`engineering-guidelines.md`](engineering-guidelines.md) 及对应主题文档为准；文档入口见 [`README.md`](README.md)。

## 1. 接任务与建立边界

1. 先读根 [`AGENTS.md`](../AGENTS.md)，再读与改动相关的规范和代码；不要仅凭历史对话、文件名或推测假定当前实现。
2. 检查 `git status`、现有 diff 和目标文件。区分当前任务改动与用户已有的未提交内容；不清理、不恢复、不覆盖无关改动。
3. 说清要解决的行为/问题、影响层、允许改动范围、明确不做的事和兼容性边界。规格尚未确定时先澄清关键决策，不要自行发明业务语义。
4. 搜索相似实现、调用链、测试、生成文件和文档；复用现有服务、模板、Adapter 与数据管道，避免平行体系。

## 2. 定义可验证的验收标准

开始编辑前，为任务列出具体验收项：

- 交付物与允许触碰的文件/模块；不在范围内的文件不得顺手重构。
- 用户可观察的行为、数据/安全不变量、失败与回退行为。
- 必须同步的 OpenAPI 生成物、数据库迁移、文档、配置模板或任务注册。
- 应运行的定向测试与质量门；说明哪些检查不适用及原因。

跨栈变更按实际需要贯通 service → schema → route → 前端 API/client/types → 页面/组件 → OpenAPI 生成物 → 测试。纯文档或配置整理不因模板而运行无关的产品测试。

## 3. 实施与委派边界

优先做最小、可审阅的改动。涉及架构、安全、数据库迁移、数据可信度或跨域权衡的决策由主执行 Agent 负责；实现不完整的上游公式或协议时，明确标记未知，不用猜测补齐。

只有当前运行环境的授权与工具策略允许委派，且并行能实际缩短工作时才拆分任务。适合拆分的工作包括只读检索、边界清晰且文件互不重叠的实现、独立文档整理或验证；小任务、强依赖对话上下文的工作、规格未定工作不委派。

委派前：

- 为每个子任务写自包含说明，给出背景、权威文档、文件边界、禁止事项、产物和可执行的验收命令。
- 明确不同执行者的文件集合互不重叠；不把架构/安全取舍悄悄交给实现者决定。

收回后：

- 检查实际文件与 diff，而不是只接受口头完成说明；检查范围、正确性、生成物和测试输出。
- 主执行 Agent 对合并结果和最终验收负责；不合格的结果修正或拒收。

## 4. 分层验证

- 按规则实际实现的位置测试；纯函数/服务逻辑优先用确定性单测。不要在前后端重复断言同一投影或解析行为。
- 上游数据、Git 生命周期和同步失败逻辑用 fixture、临时目录、注入的 runner 测试；pytest 不访问外部网络，也不执行真实 Git。
- 先运行受影响范围的定向检查，再按改动风险和项目门禁决定是否运行完整套件。API/数据库变更另核对生成物/迁移；文档变更核对链接与 diff。
- 环境、依赖或既有基线导致检查不能通过时，保留准确的命令、计数与失败原因；不要修改无关代码来掩盖，也不要把局部通过说成全绿。

测试设计及领域不变量见 [`engineering-guidelines.md`](engineering-guidelines.md)；项目质量门见 [`develop.md`](develop.md)。

## 5. 结束与结果报告

结束前再次检查完整 diff、未跟踪文件和 `git diff --check`。确认没有意外改动、死链接、遗漏的迁移/生成文件或被删除的用户内容。

最终报告至少说明：

1. 做了什么、主要文件在哪里；
2. 实际执行的检查命令与结果；
3. 未运行的检查及原因；
4. 未解决风险、基线失败或需要用户采取的后续动作。

不得仅以“完成”代替证据；不得用“通过”概括未运行或失败的质量门。

## 可选 MCP 工具

仓库不自动注册或启用 MCP 服务。以下服务按需由开发者手动加入自己使用的 Agent 配置；对 Codex CLI，可使用 `codex mcp add`（先运行 `codex mcp add --help` 确认本机 CLI 语法）。这些命令只修改本机配置，不提交密钥或机器专属设置。

| 服务 | 用途 | Codex CLI 示例 |
|---|---|---|
| Ant Design MCP | 查询 Ant Design 5 组件文档与用法 | `codex mcp add antd -- npx -y @ant-design/cli mcp --version 5.22.7` |
| Context7 | 检索库/框架的当前文档；如服务要求授权，只在本机完成 | `codex mcp add context7 --url https://mcp.context7.com/mcp` |
| Playwright MCP | 浏览器自动化与页面验证 | `codex mcp add playwright -- npx -y @playwright/mcp@0.0.83 --headless` |

以上命令记录的是迁移前仓库使用过的端点/参数，尤其 Playwright MCP 版本可能已过时；使用前请核对各服务当前的官方安装说明。其他 Agent 按其本机文档手动配置。移除本机配置可用 `codex mcp remove <name>`。
